# Attention Agent

This global background participant uses the shared private runner. Its instructions describe the attention goal. Each evaluated thread supplies only its ID, evidence revision, visit statistics, readable text length and most recent completion time. Each hide goes through the active batch receipt and current evidence check. A batch may retain every card.

The Runtime owns durable visits, deadlines and Overview visibility. A normal detail entry counts once across historical execution navigation. Foreground updates report cumulative milliseconds. Search can still match metadata and indexed body content. Opening a search hit or starting a new execution restores the card, even while the agent is disabled.

The independent fallback runs every 24 hours. Crossing from below 20 visible ordinary threads to at least 20 schedules an early review. The latest completed execution's first foreground read schedules that thread after one hour. Viewing it again adds evidence without moving this deadline. A successor invalidates the old wake and any earlier decision. Retries reuse the shared runner's receipts. Settings default to enabled and inherit Moku, with the ordinary independent profile option.

The Runtime SQLite replay uses the real Application host, a scripted native Harness and the injected hide tool. The clock-driven Runtime regression covers the three triggers and stale writes. The native Overview production replay opens a collapsed search result and returns to ordinary browsing.
