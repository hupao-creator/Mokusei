# Talk 与 Note 的同层交接

## 问题与规格

用户提供的 `录屏2026-11-04 18.39.22.mov` 为 3144×2088、7.375 秒，
轨道名义帧率 56fps，SHA-256 为
`b8efb2b2f4d70eb8c2e794c6c7be7d325b79d5a45252ae62f7de9c0bf4766e48`。AVFoundation 抽取的实际 0.975 秒画面是普通 Talk，
1.15 和 1.2417 秒的中间帧可见 Note 正文与底部 Talk 重叠；
1.4917、1.9917 和 3.4917 秒画面是 Note 与底部 Talk 同时可见。
现有布局把 Note 放在保留消息行上方，沿高度展开；即使几何位置稳定，仍然表达了
“从气泡下面抽出另一层内容”。这次改成同一胶囊内的替换阅读。

- 展开：Talk 原地淡出，单一玻璃壳扩展，Note 在壳体抵达后淡入。
- 收起：Note 先淡出，壳体返回消息或驻留尺寸，再恢复当前有效的 Talk。
- Note 的底部只保留持久眼睛、History 和 Stop/语音操作，不重复展示消息。
- 快速反向从当前几何继续，旧动画完成回调不得改写新意图；覆盖路由、输入、
  不可见窗口和 Reduce Motion 直接收敛到当前目标。
- 隐藏内容保留原生视图身份和滚动状态，但退出命中与辅助功能树；Note 完整入场后
  才具备阅读曝光资格。关闭意图立即撤销该资格。
- Talk 的数据仍由原 scene 管理。已展示消息的 60 秒期限继续，Note 内到来的新消息
  到恢复可见时才开始期限；不缓存、不复活已过期消息。
- 输入草稿、语音媒体、dispatch 详情、Note 数据/revision、Markdown 链接均沿用原归属。

实现集中在生产 Dock 的呈现状态与布局；不修改悬浮栏状态文案或单行截断。
两项工作若同时编辑 Dock 或其 README，集成时可能有文本冲突，需保留两边的局部改动。

## 实现与静态审阅

生产 Dock 区分用户打开意图、壳体展开、正文可见、入场完成和挂载寿命。
100ms 退场、420ms 壳体行程、120ms 入场依次交接，眼睛与必要操作持续存在。
完成回调用 generation 校验；无需快照、消息副本、延迟卸载任务或第二个玻璃层。
壳体采用逻辑完成点交接正文，避免等候弹簧完全移除时的长尾空壳。

隐藏消息保留原本宽度和 48pt 操作预留，不因 Note 的 History 重排；Note 的页脚不再
以消息行高度占位。正文、History 的命中和辅助功能资格与入场完成同步；关闭意图立即
撤销资格。Note 的原生曝光 probe 在视口可读后才领取打开 generation，处理保留 renderer
时的快速重新打开。已展示 Talk 的 deadline 保留，新 Talk 被 Note 遮盖时不启动 deadline。

源码审阅覆盖关闭按钮、Escape、外部点击、眼睛转输入、权限/覆盖路由、语音控制、
消息替换/过期、窄窗口与无消息路径。它们是审阅结果，不能替代完整应用动态交互验收。
