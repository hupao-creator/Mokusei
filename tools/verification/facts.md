# 当前事实与验证索引

本索引连接事实的所属文档、生产边界和验证证据；规格正文仍在所属文档。
实现证据指向当前仓库的产品与基建源码，不包含外部工作树或未落地能力。
完整入口和证据界限见[逐文档覆盖表](coverage.md)。Git 保存变更与设计历史。
跨模块查找状态、转换条件与观察入口见[状态机清单](../../design/state-machines.md)。

## 验证主责与当前能力

| 主责 | 边界 | 此源码的实际能力 |
| --- | --- | --- |
| PBT | Moku runtime 的准入、状态、不变量、取消及持久性 | 常规运行 Go Rapid、HTML fuzz 、原生几何及 Collection 占格属性，挂载状态和 native system 为可选。每项属性的判据见 [PBT 清单](pbt/README.md) |
| e2e | 用户交互及跨组件/协议流程 | 独立 manual workflow 运行 OVERVIEW、READ 和 SETTINGS，也可单选 COLLECTION。COMPOSER 使用人工系统 AX。模型输入由确定性 peer 提供。[交互清单](../e2e/README.md) |
| benchmark | 用户体验：打开/滚动/输入响应、输出时交互、资源开销 | [场景与预算](../benchmarks/gate/UX.md)、配对退化判定和显式 dispatch 已实现；预算未实机校准，缺失采集/归因能力会阻塞，不能推断产品性能通过 |
| 构建/静态 | 格式、依赖、注册、vet、Go/Swift 编译 | Makefile 与 CI 可执行；`Complete coverage` 聚合构建/静态与常规 PBT，不是代码覆盖率或完整行为认证 |

普通单测不是验证 boundary。显式 Rapid 反例有独立执行与输入身份见证，
[CLI e2e](pbt/verify.py)检查输入拒绝和真实属性执行，
不增加 Runtime 属性数量。[性能晋升](../benchmarks/gate/README.md)保留按 digest
定位的批准报告快照，晋升命令结果与性能 verdict 分开；合成机制检查不认证产品性能。
额外 PBT 必须说明独有缺陷覆盖与补充理由，不能替代主责。
没有实现或没有证据的覆盖保持明确缺口；`blocked`、`skipped`、未运行和其他提交结果不算通过。
