# Production native talk replay

See [the production talk contract](../../../app/macos/Sources/Host/MokuScene/README.md) for behavior and verification limits.

```sh
make check
MOKU_TALK_NATIVE_FIXTURE="$PWD/.scratch/moku-talk-production/tool-records.json" ./scripts/go.sh run ./tools/verification/moku
python3 tools/verification/moku-talk/run.py --skip-build --records .scratch/moku-talk-production/tool-records.json
```

The Go replay exports audit records generated by the production Coordinator's real talk binding in an isolated fixture world. This replay feeds those records through the production Catalog, WorkspacePresentation, scene and Dock, checks native text/eye/scroll geometry and captures only its own WindowServer window with ScreenCaptureKit. Text replacement retains the same native scroll view, including while height animates. No user runtime, live provider, microphone, voice session or application restart is involved.

The remaining intervention, hidden-state and voice-control inputs are explicit fixtures. They prove layout/priority, not live provider/voice transport. The default evidence directory is `.scratch/moku-talk-production/evidence`; `report.json` records metrics and scope. A native capture failure is a replay failure, never replaced with a synthetic glass screenshot. Run after the current SwiftPM build completes; do not overlap package builds against the same scratch path.

The same export/replay now includes the production `create_thread` binding's
pending, successful and failed audits. It checks the approved 400×58 dispatch
row, Vision OCR of visible model/effort pixels and alignment, voice-mode admission, compact dark layout,
real click-to-input-details and Escape dismissal. The voice-mode xhigh field is
an explicit public audit fixture; the real mock target schema has only model.
The mock Harness uses the production Codex logo. See
[the dispatch contract](../../../app/macos/Sources/Host/MokuScene/README.md) for data and delivery scope.

Voice dispatch also mounts the production loudness-driven `NativeVoiceCloud`
with fresh scalar fixture input. A text-free strip of own-window pixels must
move while configuration OCR and detail clicks continue to pass. The separate
Moku voice-cloud replay covers the actual PCM analyser; neither replay opens a
microphone or connects to the active runtime.
