# Overview 时钟渲染优化 · 2026-11-13

将运行时钟的数字淡入淡出移交 Core Animation，共享有限大小的字形缓存。计时频率、隐藏暂停、恢复校时、完成时间和正文负载保持原有行为。未改变布局算法。

本次只比较 App 进程 CPU。两份签名生产 Release 包使用相同外部采集器、10 张预先存在的卡片和 8 秒正式窗口；先测最终候选 `d2`，再测原版本 `a2`。CPU 100% 表示占用一个核。完整制品身份、原始数值及状态见 [JSON](2026-11-13-runtime-clock.json)。

| 场景 | 原版 App CPU | 优化后 App CPU | 相对下降 | 原版 / 优化后内存峰值 |
| --- | ---: | ---: | ---: | ---: |
| 运行中，等待输出 | 34.36% | 28.69% | 16.5% | 147.5 / 140.0 MiB |
| 正文更新 | 61.16% | 49.74% | 18.7% | 151.7 / 144.6 MiB |

正文负载仍是每卡每秒 2 个 64 字节 reasoning 片段、每累计 512 字节产生完整进度消息。两边均发送 160 个片段、30 条进度及最终消息，20/20 个 CHECK 检查点到达；产品与业务结果均为 `passed`。

这是一组单机有限样本的描述性结果。全部测量仍为 `incomplete`、比较仍为 `not-comparable`：未认证原生 hitch，子进程生命周期和退出 CPU 不完整。候选正文场景另有一个短命 `git` 子进程缺失；App 在每次资源采样中均存在。不能据此宣称无卡顿、总进程树成本或整机能耗下降。

首次渲染、拖动、边输出边拖动及其他卡数未重测。没有将此前尝试 XCTest 的基线混入本表。
