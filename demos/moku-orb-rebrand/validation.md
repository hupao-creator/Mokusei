## 诊断与处理

- 去掉眼睛空位后，旧手势测试的 x=32 已落入可滚动正文；改为真实的 18pt 留白内
  取点，继续验证「已由正文取得的滚动不能中途抢给 Note」和「新手势能打开 Note」。
  更宽的转写正文使旧样本不足两个视口，扩大样本文本，原溢出断言不放宽。
- 外观回放曾向已经停用的历史语音背景参数注入探针。移除该旧探针，仍逐一检查
  两个实际原生编辑器的深色外观、文本、身份和普通编辑器不受污染。
- 横向回放的 AppKit host 没有 SwiftUI App scene，需显式提供 active phase。
  固定 180ms 后注入阻塞已经靠近当前单调曲线末尾；改为观察到首个移动帧再注入，
  保留原有至少三个不同位置、超过 20pt 位移及全部中间帧判据。
- 历史输入的按住检查已经并入普通点击用例，实际是 7 个 `@Test`；修正启动器
  遗留的 8 个计数，所有用例和按住检查均保留。
- Agent 点击回放最初在非 key window 中发送事件。先建立前台窗口条件，但不
  对待测编辑器强制聚焦，继续用实际点击和键盘事件验证焦点与草稿。
  最终提交复核还捕获到手势监视器的 SwiftUI 包装层直接命中了输入位置；
  将监听视图固定在原点、零尺寸挂载，保留坐标转换与本地监听，杜绝占据点击区域。
  同时沿用既有语音场景，用多行草稿确认仅语音控制时不遗留编辑器的高度。
  一次早期键入超时伴随 IMK 日志，单凭这点不能判断因果。补充诊断后明确捕获到
  `dao` 等非 fixture 字符进入测试编辑器；该前台用例现在只接收带私有标记的测试
  键盘事件，不影响其他应用或系统输入源，仍检查真实点击、焦点与精确草稿文本。
